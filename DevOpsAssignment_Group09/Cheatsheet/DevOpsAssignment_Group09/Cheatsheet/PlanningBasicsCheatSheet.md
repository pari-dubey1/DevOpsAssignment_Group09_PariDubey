# Planning Basics Cheat Sheet

## Planning Phase in DevOps

The **Planning phase** is the first stage of the DevOps lifecycle. It focuses on understanding project requirements, identifying user needs, setting objectives, prioritizing tasks, estimating resources, and creating a roadmap for development and deployment.

### DevOps Lifecycle

Plan → Code → Build → Test → Release → Deploy → Operate → Monitor

---

## Main Objectives of Planning

- Understand project requirements
- Identify user and business needs
- Define clear project goals
- Break the project into manageable tasks
- Prioritize important tasks
- Estimate time and resources
- Identify possible risks
- Create a roadmap for development

---

## Planning Process

### 1. Gather Requirements

Understand what users and stakeholders need from the project.

Requirements can include:

- Functional requirements
- Non-functional requirements
- User expectations
- Business requirements

### 2. Define Objectives

Clear and achievable goals should be defined for the project.

A good objective should follow the **SMART** principle:

| Letter | Meaning |
|--------|---------|
| S | Specific |
| M | Measurable |
| A | Achievable |
| R | Relevant |
| T | Time-bound |

### 3. Break Down the Work

A large project is divided into smaller and manageable tasks. This can be done using a **Work Breakdown Structure (WBS)**.

```text
Project
│
├── Requirement Analysis
├── Planning
├── Development
├── Testing
└── Deployment
```

### 4. Prioritize Tasks

Tasks are arranged according to their importance and urgency.

- **High Priority** – Must be completed first
- **Medium Priority** – Important but can be completed later
- **Low Priority** – Can be completed when time is available

### 5. Estimate Resources

The resources required for the project should be identified.

Resources may include:

- Team members
- Time
- Budget
- Software tools
- Hardware or cloud resources

### 6. Identify Risks

Possible problems should be identified before development begins.

| Risk | Possible Impact |
|------|-----------------|
| Changing requirements | Project delay |
| Limited resources | Reduced productivity |
| Technical issues | Development problems |
| Poor communication | Coordination issues |

### 7. Create a Roadmap

A roadmap provides a clear direction and timeline for completing project tasks.

```text
Requirements
     ↓
Planning
     ↓
Development
     ↓
Testing
     ↓
Deployment
```

## Tools Used in DevOps Planning

### 1. GitHub / Git

**Git** is a version control system used to track changes made to a project.

**GitHub** is a cloud-based platform used to host repositories and collaborate with team members.

#### Uses

- Version control
- Tracking project changes
- Team collaboration
- Managing repositories
- Creating branches
- Creating and reviewing pull requests

#### Basic Workflow

```text
Create Branch → Make Changes → Commit → Push → Pull Request → Merge
```

---

### 2. Jira / Trello

**Jira** and **Trello** are project management tools used to organize, assign, and track tasks.

#### Uses

- Creating tasks
- Assigning tasks to team members
- Setting priorities
- Managing backlogs
- Planning sprints
- Tracking project progress

#### Example Workflow

```text
To Do → In Progress → Testing → Done
```

#### Important Agile Concepts

- **Product Backlog** – List of all project requirements and tasks
- **Sprint** – A fixed period for completing selected tasks
- **User Story** – A feature described from the user's perspective
- **Sprint Planning** – Selecting and planning tasks for a sprint
- **Daily Stand-up** – A short meeting to discuss progress and blockers

---

### 3. Microsoft Excel / Google Sheets

**Microsoft Excel** and **Google Sheets** can be used for project planning, scheduling, tracking, and documentation.

#### Uses

- Creating task lists
- Managing project schedules
- Tracking deadlines
- Assigning responsibilities
- Monitoring project progress
- Maintaining project data

#### Example Task Tracker

| Task | Assigned To | Deadline | Status |
|------|-------------|----------|--------|
| Requirement Analysis | Team Member 1 | Week 1 | Completed |
| Task Planning | Team Member 2 | Week 1 | In Progress |
| Development | Team Member 3 | Week 2 | Pending |
| Testing | Team Member 4 | Week 3 | Pending |

---

## Quick Tool Summary

| Tool | Main Purpose |
|------|--------------|

| Jira / Trello | Task and project management |
| Excel / Google Sheets | Planning, scheduling, and progress tracking |

## Role of Planning in DevOps

The Planning phase helps the Development and Operations teams work toward common goals.

It improves:

- Collaboration
- Communication
- Task management
- Resource utilization
- Risk management
- Project visibility
- Development efficiency

---

## Quick Revision

**Planning in DevOps = Requirements + Goals + Tasks + Priorities + Resources + Risks + Roadmap**

### Planning Flow

```text
Understand Requirements
        ↓
Define Goals
        ↓
Break Down Tasks
        ↓
Prioritize Work
        ↓
Estimate Resources
        ↓
Identify Risks
        ↓
Create Roadmap
        ↓
Start Development
```

## Key Takeaway

The **Planning phase** provides the foundation for the entire DevOps lifecycle. Proper planning helps teams understand requirements, organize tasks, allocate resources, manage risks, collaborate effectively, and deliver software efficiently.
